Autonomous Multi-Agent Architecture & Protocol

Overview of the 3-agent orchestration engine, A2A communication, and self-correction loops.

1

Dynamic Discovery & Interrogation

At workflow startup, Agent C (Supervisor) queries Agent A (OpenAI) and Agent B (Claude): "What do you do?". Profiles, models, and capabilities are registered in SQLite (orchestration.db).

2

Task Dispatch & Technical Drafting

Agent C dispatches the task objective to Agent A (OpenAI). Agent A acts as the primary builder, generating technical proposals, architecture designs, and Python implementations.

3

Quantitative Quality Gate

The draft is routed to Agent B (Claude) for comprehensive verification. Claude inspects edge-cases, vulnerability points, and outputs a quantitative score (0–100) with actionable recommendations.

4

Supervisor Self-Correction Loop

If Claude's quality score falls below the user's Acceptance Gate (e.g. 80), Agent C intervenes! The Supervisor commands Agent A to execute Revision 2 addressing the flaws until approval is achieved.

Switching between Simulation Mode & Live API Mode:

The console includes an autonomous simulation engine so you can test complete end-to-end workflows with zero API costs. To connect your live API keys: 

# In the root .env file, add your OpenAI and Anthropic API keys:
OPENAI_API_KEY=sk-proj-your-openai-api-key
ANTHROPIC_API_KEY=sk-ant-your-anthropic-api-key

# Then switch the "Live API Mode" toggle in the top-right header!
