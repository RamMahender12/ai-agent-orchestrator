Multi-Agent Orchestration Architecture

This system implements the exact architecture requested by your client: an autonomous Supervisor Agent coordinating specialized OpenAI and Claude agents across 3 dedicated screens with full observability, self-correction, and token cost tracking.

1

Discovery & Registry

Agent C (Supervisor) queries Agent A (OpenAI) and Agent B (Claude) on startup: "What do you do?". Capabilities, models, and metadata are automatically recorded in an SQLite database (orchestration.db).

2

Task Assignment & Audit

Agent C assigns the objective to Agent A, tracks execution state on Screen A, and routes the draft to Agent B (Claude) on Screen B for comprehensive verification and quantitative scoring (0-100).

3

Self-Correction / Feedback Loop

If Agent B discovers flaws or assigns a score below threshold: Agent C intervenes! C formats precise corrective guidance and instructs Agent A to execute Revision 2. The cycle repeats until approved.

4

Token & USD Cost Telemetry

Every token generated by OpenAI and Claude is tallied with official model pricing. Exact expenditures for Agent A, Agent B, and Agent C are tracked per step and aggregated for audit compliance.

How to Switch to Live API Keys:

The system is pre-configured with a realistic zero-cost simulation mode so anyone can test it immediately. To connect real API keys:

# In the project root, open .env and set your keys:
OPENAI_API_KEY=sk-proj-your-openai-key-here
ANTHROPIC_API_KEY=sk-ant-your-claude-key-here
SIMULATION_MODE=false

Then restart the server or uncheck "Simulation Mode" in the dashboard.
